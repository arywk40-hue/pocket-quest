# Field trial: record what actually happened

Try the case with three consenting friends on a familiar public tree-lined walk. Do not invent participant feedback, durations, accuracy, or event photographs.

Before leaving:
1. Record the computer/phone model, OS, browser, Gemma GGUF/projector names and SHA-256 hashes, inference settings, and loaded model alias.
2. Run one genuine photo review and check a model error case.
3. Generate the three ElevenLabs chapters and inspect a real Sentry trace if entering those categories.
4. Download the field kit. Open it with connectivity disabled on the intended phone. Confirm transcript, audio if prepared, photo selection, journal export, and reopen behavior. File previewers are not necessarily browsers.

For each participant record: setup seconds, walk minutes, visible app seconds, clues completed, accepted/uncertain/rejected decisions, manual overrides, and one direct feedback quote with permission. Visible app time is an approximate in-app metric, not OS-wide screen time or a medical measure of wellbeing.

Afterward compare model decisions with human review on at least 15 independently labelled photos: five relevant, five unrelated, five ambiguous. Separate clue types, log model settings and latency, and preserve the original labels. Do not tune against and then report the same examples as an untouched test. A small convenience sample is illustrative rather than proof of broad performance.

Report false acceptance, false rejection, uncertainty, p50/p95 latency, and failures. Include both favourable and unfavourable examples. Do not present manual confirmations as model successes.
